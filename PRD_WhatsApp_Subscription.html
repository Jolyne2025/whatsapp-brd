一、背景与目标

1.1 背景

  • WhatsApp 全球日活 25 亿+，欧洲渗透率 ≥ 50%，在 63/100 个国家/地区排名第一（2022 年起保持领先），DE/FR/IT/ES 核心买家群天然在 WhatsApp。

图：全球消息应用覆盖率地图（来源：订阅增长策略 BRD 调研）——欧洲大陆（含 DE/FR/IT/ES）以 WhatsApp 为主流，支撑渠道选择。
  • 邮件 EDM 打开率持续走低，需要高触达率、低频高价值的补充触达渠道；WhatsApp 营销已读率 40–50%（系统消息 62.8%），远高于 EDM。
  • 营销消息定位为二次触达（承接 PUSH/EDM 已触达未 AB 的用户），非独立拉新追单（站外追单已证伪，−7.7pp）。
  • 订阅收集是漏斗最上游、重中之重：国际站累计订阅已 900w+（2026-08-10 手册口径，历时 1.5 年+，旧文档 500w 已过时），8 大订阅入口全站铺设；Visable 从 0 开始，订阅入口必须从一期就铺设、多点位并行。
  • 国际站实测规律："意图越高转化越高"（沟通页弹窗 8.6% ≈ 注册联动 10% >> 订后页 2% >> 首页大曝光 0.2–0.4%）——点位设计必须锚定高意图场景，不做低意图大曝光。

1.2 目标（UC-419 口径）

1.3 本 PRD 范围

本 PRD 覆盖订阅收集链路（UC-419 的前置与输入）：订阅点位设计、double opt-in 流程、订阅态三态服务、订阅后 onboarding、同意记录与埋点、护栏与合规、衡量指标。

Out（不在本 PRD）：营销消息发送策略本身（圈人池、频次 A/B）→ 由 UC-419 主体方案承接；系统消息（conversation 提醒 / 催复提醒）→ PRD_Reminder；商家侧通知 → 述合。

2.2 点位 1：询盘发出后弹窗（P0，灰度首选）

  • 触发时机：询盘/RFQ 提交成功事件（感谢页渲染后 1s 弹出）。
  • UI 交互：成功页底部弹窗（半屏 modal），主按钮「开启 WhatsApp 消息提醒」，次按钮「以后再说」（关闭后本轮不再弹出，下次提交询盘再触发）。
  • 授权文案（示例，以 Legal 确认后定稿）：
开启后，我们将通过 WhatsApp 向您发送：① 询盘回复提醒（供应商回复第一时间通知）② 与您采购需求相关的产品推荐（每周最多 1 条）③ 重要通知。您可随时在账号设置或回复 STOP 退订。详见[隐私声明]。
  • 设计理由：① 用户刚提交询盘，有明确的回复期待，授权意愿最高；② 国际站实测锚点：沟通页弹窗最终订阅率 8.6%（1v1 沟通后 ab3 152k → 授权 13k），与本测算基准 15%×65%=9.75% 高度吻合——该点位是唯一有国际站同场景实测背书的高转化点位；③ 场景绑定授权（"接收询盘回复提醒"）是合规最强形态，与系统消息（conversation 提醒）同源，一次授权可同时服务系统消息一级 opt-in 与营销二级确认入口；④ 灰度期只做这一个点位，链路最短、变量最少，便于评估 double opt-in 完成率。
  • 曝光基数（Redash 实测）：1,083 req/日（QDR 855 + RFQ 228，剔除 7/22–24 异常日），去重后 592 buyer/日——远高于反推所需 1,693/日曝光的一半以上，瓶颈在转化率而非流量。
口径说明：上述 592 buyer/日含 Nexus（request_origin='alibaba'）——Nexus 询盘发生在 Alibaba.com 场域，Visable 无法在那做订阅弹窗，应予排除。按 Visable 看板标准口径（request_origin IN ('app','web')），Nexus 约占 AB 层询盘买家的 ~25%，修正后 Visable 站内可用曝光基数约 810–840 req/日、440–450 buyer/日（待 Redash 精确取数后校准）。修正后的曝光基数仍高于反推所需的单点点位需求（~730/日），但缓冲空间大幅收窄。
  • 留证：consent_id、用户 id、点位标识、同意时间、文案版本号、设备信息、IP 国家（不存原始 IP）。
  • 弹窗形态对标实拍（国际站沟通页弹窗三变体——8.6% 转化锚点的 UI 依据，均已在 §2.1 图集列示）：

2.3 点位 2：手机号验证后二次询问（P0）

  • 触发时机：手机号验证码校验成功回调（含注册中、账号设置中、下单前验证等所有验证场景）。
  • UI 交互：验证成功后弹窗（同 2.2 样式），主按钮「开启 WhatsApp 消息提醒」，次按钮「以后再说」。
  • 设计理由：① 手机号已验证真实有效 → 二级确认（WhatsApp 模板消息）送达率最高，double opt-in 完成率预期优于其他点位；② 该点位是注册链路的自然延伸，覆盖未在注册页勾选的用户，形成互补；③ 曝光基数实测 887/日（ep 770 + wlw 117），与点位 1 同量级。
  • 对标警示（测算 5.3b 结论）：国际站订单页 WAP 组件实测仅 2%，本点位基准假设 8%×65%=5.2% 偏高——验证后询问虽高于订后页（号码已验、场景有即时利益），但需灰度期实测校准，若显著低于 5% 需提前加码点位 1/存量激活。
  • 频控：同一用户 30 天内最多弹 2 次（首次关闭 + 30 天后 1 次），避免打扰。
  • 留证：同 2.2。

2.4 点位 3：注册页独立勾选框（P0）

  • 位置：注册流程最后一步（提交按钮上方），独立于服务条款勾选（不得捆绑）。
  • UI 交互：默认不勾选；勾选框文案：
☐ 通过 WhatsApp 接收询盘回复提醒与产品推荐（每周最多 1 条，可随时退订）
  • 勾选后展开说明行：频次、内容类型、退订方式（Subscription Center / STOP）、隐私声明链接。
  • 设计理由：① 注册期是用户触点最密集、改造成本最低的入口；② 对标：国际站登录/注册页为订阅核心入口（手机号注册联动实测 10%），但其为"默认勾选/直接授权"形态——Visable 欧洲合规从严（默认不勾选 + double opt-in），基准假设 5%×65%=3.25% 为 10% 的从严折半，测算判定"合理从严"；③ 曝光基数实测 946/日（ep 820 + wlw 125），与点位 1/2 同量级。

2.5 点位 4：Subscription Center（P1，达标关键路径）

  • 位置：账号设置 → 通知偏好（复用 UPR-55 Lifecycle 入口，不新建页面壳）。
  • 功能：

1. 查看当前 WhatsApp 订阅状态（未订阅/待确认/已订阅/已退订）；

2. 开启：未订阅用户点击开启 → 进入 double opt-in 流程（发确认消息）；

3. 关闭（退订）：即时生效并同步订阅态服务，无需二次确认（退订零摩擦）；

4. 偏好设置：品类（按采购品类圈选）+ 频次（每周 1 次 / 仅重要消息）；「仅重要消息」自动降频，与频控统一；

5. 手机号变更：更新手机号后订阅状态置「未知」，需重新验证并确认（号码即触点标识，换号必须重授权）。

  • 对标：国际站个人中心 MA 模块 1%（40w UV → 4k/日），是站内低频稳定入口；竞品 TEMU notification 页可设接收频率（= Subscription Center 概念）。
  • 存量激活测算（关键修正）：存量已验证用户 360w 中，真实活跃仅 ≈ 13.7w（3.8%，有登录记录）——SC 激活的现实池子是活跃池而非全量。按活跃池 0.5–1%/月激活 ≈ 5,000–10,000（212 天累计），恰好补足站内新触点基准缺口的 8,000–9,000。
  • 设计理由：① 合规退订链路的站内枢纽；② 系统消息与营销消息共用的偏好管理入口；③ P1 期（10 月）即上线——达标与否取决于它，不能拖到爬坡后期。

2.6 点位 5：站外入口（P2，一期不做）

  • 形态：IG/FB 主页链接、独立落地页（表单勾选或回复关键词订阅）。
  • 二级确认：国际站实操范式为绑定码流程：站内点击订阅 → wa.me 唤醒 WhatsApp 带入话术/绑定码（BIND-xxx）→ 用户发送绑定码 → 系统回欢迎话术 → 订阅成功；站外话术 "I would like to subscribe alibaba.com channel."。Visable 站外入口可复用此范式（无 WhatsApp 对话上下文时走短信/邮件确认码）。
  • 一期不做原因：① 链路最长、合规风险最高；② 订阅量爬坡前站内四触点已够；③ 站外号码无法与站内用户 id 关联，埋点归因断裂。待站内点位跑通、Legal 确认后二期评估。

2.7 点位设计原则（国际站规律落地）

意图越高转化越高（沟通 8.6% ≈ 注册 10% >> 订后 2% >> 首页 0.2–0.4%）点位 1（高意图）为主力，点位 2/3 为补充；不做首页大曝光入口（100w UV 级仅 0.2–0.4%，效率极低，P2 正确）
