WhatsApp 消息模板（Message Templates）创建调研

调研日期：2026-08-25 ｜ 面向 Visable 直连 Meta Cloud API 通道（自建模板管理/送审）｜ 来源：Meta 官方文档 + GuruSup 2026 指南 + ChatDaddy 出海指南

一、为什么需要消息模板

WhatsApp 的核心规则是 24 小时客户服务窗口：

  • 用户主动给商家号发消息后，开启 24h 窗口，窗口内商家可自由发送任意内容、免费；
  • 窗口外（含用户从未发过消息、或超过 24h）商家要主动联系用户（通知、营销、群发），必须使用经 Meta 审核批准的消息模板，按模板类别付费。

因此模板 = 商家主动触达用户的唯一合法载体，也是 Visable「拉快首响」通道的基础设施。项目记忆确认：直连 Cloud API 免费按量计费，但需自建模板管理/送审。

二、模板三大类别

类别典型场景审核难度相对费用（对话计费）备注
Utility 实用类订单确认、物流更新、预约提醒、账户通知、账单、订阅确认较宽松（对用户有益）最低-中等，约 $0.01-0.04/对话；欧洲约 €0.03-0.04/条内容必须与"实用目的"一致，掺入促销会被 Meta 重判为 Marketing
Marketing 营销类促销、新品、活动、弃单召回、激活挽回、Newsletter最严格（关注骚扰感）最高，约 $0.02-0.08/对话；欧洲约 €0.11/条建议 Footer 加退订选项（"回复 STOP"）提高通过率
Authentication 认证类OTP 验证码、两步验证最宽松（格式固定）最低，部分地区有免费额度有固定格式 + 自动填充按钮，Meta 提供标准化模板

分类是审核被拒的头号原因：消息同时含实用信息+营销内容 → 按 Marketing 提交，不要"包装"成 Utility 降费（易被拒，且过了也可能被举报影响账号质量分）。

与 Visable BRD 对照：Utility €0.035/条、Marketing €0.11/条的口径与 Meta 欧洲费率一致。订阅确认 onboarding 模板"争取 Utility（含订阅确认措辞）"即属此分类风险点。

三、创建方式 A：WhatsApp Manager 界面操作（无代码）

路径：Meta Business Suite → WhatsApp 管理工具（WhatsApp Manager）→ 消息模板 → 创建模板，填写：

  1. 模板名称：仅小写字母+数字+下划线，如 rfq_promo_recurring_v1；
  2. 类别：Utility / Marketing / Authentication；
  3. 语言：选择目标语言（如 en、de）；同一模板名可建多语言版本，每个语言版本独立送审；
  4. Header（可选）：无 / 文本 / 图片 / 视频 / 文档（品牌图常用于营销）；
  5. Body（必填）：正文，动态变量用 {{1}} {{2}} 占位，≤1024 字符，支持粗体/斜体；
  6. Footer（可选）：灰色小字，放免责声明/退订提示；
  7. Buttons（可选，最多 3 个）：快速回复（预设回复）或 CTA（访问网站链接/拨打电话）；
  8. 提交审核：Meta 审核通常几分钟～24 小时（第三方实测 24-48h 常见）。
另有预批准模板库：WhatsApp Manager 模板库中直接选用 Meta 预批准模板（如订单确认、物流等），即时批准，适合快速起步。

四、创建方式 B：Cloud API 编程创建（项目直连走这条）

POST 到 WABA 级接口创建：

```bash

curl -X POST 'https://graph.facebook.com/v21.0/{waba-id}/message_templates' \

-H 'Authorization: Bearer {ACCESS_TOKEN}' \

-H 'Content-Type: application/json' \

-d '{

"name": "rfq_promo_recurring",

"language": "en",

"category": "MARKETING",

"components": [

{ "type": "HEADER", "format": "TEXT", "text": "New RFQ matching your profile" },

{ "type": "BODY", "text": "Hi {{1}}, a new buying request for {{2}} was just posted. Reply to get details." },

{ "type": "FOOTER", "text": "Reply STOP to unsubscribe" },

{ "type": "BUTTONS",

"buttons": [

{ "type": "URL", "text": "View RFQ", "url": "https://www.wlw.com/rfq/{{3}}" },

{ "type": "QUICK_REPLY", "text": "Interested" }

] }

]

}'

```

关键参数：

参数说明
name模板名，小写+下划线，审核后不可改
language语言代码，如 en、de、fr、es（_IT 等变体后缀视需求）
categoryUTILITY / MARKETING / AUTHENTICATION
componentsHEADER（format: TEXT/IMAGE/VIDEO/DOCUMENT）、BODY、FOOTER、BUTTONS（URL/PHONE/QUICK_REPLY）
示例参数提交时可附 example 示例值（真实样本，如 "Michael"、"ORD-2026-001234"），帮助审核理解用途、提高通过率

管理接口（同域）：GET /{waba-id}/message_templates 列表、DELETE 删除；审核状态查询含 PENDING / APPROVED / REJECTED / PAUSED / DISABLED。

发送：模板批准后用 POST /{phone-number-id}/messages，type: "template" + 模板名 + 语言 + 变量值。

五、审核机制与通过技巧

被拒常见原因：垃圾信息风格（全大写、过多感叹号、夸大词汇"史上最低/最后机会/千万别错过"、制造恐慌）、营销伪装 Utility、含敏感信息索取、变量使用不规范、内容与声称用途不符。

提高通过率技巧（实测可将通过率提至 90%+）：

  • 用具体数字替代夸大词（"节省 €20" > "超大优惠"）；
  • 用截止日期替代恐慌语（"优惠至 3月31日" > "最后机会"）；
  • 变量按顺序连续编号 {{1}}{{2}}{{3}}，固定文本 ≥50%，每个变量前后有上下文；
  • 链接不直接放变量，用 URL 类型按钮；
  • 示例值给真实样本，不要占位符；
  • 营销模板 Footer/按钮加退订选项（Meta 鼓励，证明尊重选择权）。

六、运营规则与常见坑

规则说明
已批准模板不可修改要改文案只能新建模板重新送审 → 提交前仔细检查；高频模板可保留多版本做 A/B
模板数量上限每个 WABA 约 250 个已批准模板（跨语言合计），暂停/被拒不计入
质量分暂停用户拉黑/举报 → 模板质量分下降 → Meta 自动暂停/禁用模板；需维护账号质量
长期不用模板可能被置为 Paused，可后台重新启用
图片模板审批只审结构，发送时传具体图片；发送内容仍须合规
多语言版本同名模板每语言独立审核，建议先 EN 再按市场补本地语言
限流发送速率按账号等级（初始 250 会话/天，最高 100,000），标准档 80 msg/s

七、对 Visable 项目的启示

  1. 直连 Cloud API 需自建模板管理：建议按 BRD 模板清单（onboarding 订阅确认 / RFQ 营销 recurring / 产品推荐 / 系统消息 2 类 / 催复）规划命名规范（rfq_promo_recurring_de 等），走 API 批量创建 + 状态监控脚本；
  2. 分类策略：Utility 首批 EN+DE 措辞中性；订阅确认模板"争取 Utility"有被重判 Marketing 的风险（€0.035 → €0.11），建议提交时措辞严格交易化（确认订阅状态+偏好设置+退订，无任何促销成分）；
  3. 合规：营销类模板一律带退订（STOP）与偏好设置入口，与订阅漏斗合规要求一致；
  4. 节奏：FR/IT/ES 多语言模板建议提前与 DE/EN 并行送审，避免扩国时等审核；审核时间几分钟～24h 是常态，需预留；
  5. 费用复核：模板类别决定计费（Utility €0.035 vs Marketing €0.11），BRD 费用表需按最终获批类别回填校准。
